# 知阶 Knowledge Steps UI 设计风格规范

> 本文档是前端页面的视觉与交互基线。所有新增页面、组件和样式都应先对照本文件，再检查 [frontend/src/styles.css](../src/styles.css) 中的设计变量与组件类名，避免后续页面逐渐漂移。
>
> 配套文件：
>
> - 设计上下文与原则：[.impeccable.md](../../.impeccable.md)
> - 前端技术方案：[FRONTEND.md](FRONTEND.md)
> - 产品范围：[PROJECT.md](../../docs/PROJECT.md)

## 一、视觉定位

### 1.1 视觉语言

知阶的界面采用 Modern SaaS / AI-native 的浅色风格：

- 浅蓝紫柔光背景，带低透明度的青蓝与品蓝极光光晕。
- 轻量磨砂质感只用于顶部导航，不做大面积玻璃拟态。
- 卡片使用扩散阴影和 1px 细边建立层级，不用厚重的卡片堆叠。
- 强调“清醒、温润、克制”，视觉上像一本排版讲究的学习手册，而不是通用中后台模板。

### 1.2 反例约束

以下做法不进入本项目：

- 紫蓝渐变霓虹暗色风、大面积发光边框。
- 纯黑 `#000`、纯白 `#fff` 作为大面积底色或文字。
- 千篇一律的“图标 + 标题 + 说明”等大卡片网格。
- 渐变文字、无意义的 sparkline、装饰性玻璃拟态。
- Inter / Roboto / Open Sans 等默认字体作为视觉卖点。
- 无 hover / focus / disabled / loading / error 状态的“一次性按钮”。

## 二、全局设计变量（Design Tokens）

所有颜色、圆角、阴影、字体和间距都应从 `:root` 变量取值。页面与组件中禁止散落新的十六进制色，除非它只是某个变量的一次性派生值。

### 2.1 品牌色

| Token | 值 | 用途 |
| --- | --- | --- |
| `--primary` | `#5b61f6` | 主 CTA、选中态、核心高亮 |
| `--primary-hover` | `#4b51e6` | 主按钮悬停 |
| `--primary-subtle` | `#eef2ff` | 浅蓝底、小标签、选中背景 |
| `--cyan` | `#38bdf8` | 连接线、渐变点缀、流程步骤小标 |
| `--green` | `#10b981` | 完成、已掌握、可开始 |
| `--amber` | `#d97706` | 待补齐、提醒 |
| `--red` | `#e11d48` | 错误、失败 |

### 2.2 文字与中性色

| Token | 值 | 用途 |
| --- | --- | --- |
| `--text-main` | `#1e293b` | 主标题、核心文字 |
| `--text-sub` | `#475569` | 正文、副标题 |
| `--text-muted` | `#94a3b8` | 弱化辅助、未选中项 |
| `--border-subtle` | `#e2e8f0` | 基础细线边框 |
| `--border-card` | `rgba(226, 232, 240, 0.8)` | 卡片细边 |

### 2.3 表面与底色

| Token | 值 | 用途 |
| --- | --- | --- |
| `--bg-page` | `#f8fafd` | 页面底 |
| `--bg-card` | `#ffffff` | 主卡片 |
| `--bg-badge` | `#f1f5f9` | 胶囊浅灰底 |

### 2.4 圆角

| Token | 值 | 用途 |
| --- | --- | --- |
| `--radius-pill` | `9999px` | 按钮、胶囊、搜索框 |
| `--radius-card` | `20px` | 主卡片、看板、结果 Hero |
| `--radius-item` | `10px` | 内部列表项、微卡片 |

### 2.5 阴影

| Token | 值 | 用途 |
| --- | --- | --- |
| `--shadow-card` | `0 20px 40px -15px rgba(91, 97, 246, 0.08), 0 0 1px 1px rgba(226, 232, 240, 0.8)` | 主卡片 |
| `--shadow-float` | `0 12px 28px -6px rgba(0, 0, 0, 0.06)` | 悬浮装饰、气泡 |
| `--shadow-search` | `0 8px 30px rgba(91, 97, 246, 0.07)` | 搜索框聚焦 |

### 2.6 字体与排版

字体栈统一为：

```css
"Segoe UI", "Microsoft YaHei", system-ui, -apple-system, sans-serif
```

- 正文不小于 14px，辅助文字可降到 12px，脚注 11px。
- 主标题使用 `clamp()` 流式字号，不写死像素。
- 首页 Hero 标题字号约 `clamp(34px, 4vw, 54px)`，字重 800，字距略收紧。
- 段落行高 1.8，颜色使用 `--text-sub`，不默认纯黑。

## 三、版式与网格

- 最大版心宽度：`1240px`，页面居中。
- 页面左右最小安全间距：`24px`，小屏降为 `16px`。
- 顶部导航高度：`64px`，固定顶部，带磨砂白背景和 1px 底边。
- 页面主体上下内边距约 `32px / 64px`，底部标语区独立 `40px` 内边距。
- 首屏 Hero 为左右不对称栅格：左侧文案约 `0.9fr`，右侧实景看板约 `1.1fr`，移动端堆叠。

## 四、基础组件规范

### 4.1 按钮

按钮层级从高到低只使用四种：

- `.primary`：胶囊主按钮，底色 `--primary`，白色文字，悬停换 `--primary-hover`。
- `.outline`：胶囊次级按钮，白底、细边、灰蓝文字，悬停变浅蓝底。
- `.textbutton`：文字按钮，主蓝色，用于返回、次要操作。
- `.search-submit`：40px 圆形主按钮，用于搜索提交，悬停轻微放大。

禁用态统一降低透明度，保留 `cursor: not-allowed`。所有按钮必须有 `hover`、`focus-visible`、`active`、`disabled` 状态，不能只做默认态。

### 4.2 输入框

- 核心搜索框高度 `56px`，胶囊圆角，白底细边，聚焦时变浅蓝边和 `--shadow-search`。
- 输入框内左侧放 20px 搜索图标，右侧放 40px 圆形提交按钮。
- 表单校验错误用 `.field-error` 显示在输入框下方，颜色 `--red`，并绑定 `role="alert"`。

### 4.3 标签与徽章

- `.badge`：浅蓝底、主蓝字，小圆角，用于阶段和结果提示。
- `.chip`：白底或浅灰底胶囊，带 emoji 前缀，悬停变浅蓝底。
- `.tag`：内部信息分类，允许用青、绿、蓝等低饱和派生色做语义区分。

### 4.4 卡片与列表

- 主卡片统一 `.card`：白底、细边、`20px` 圆角、柔和阴影。
- 不嵌套卡片；卡片内部用留白、分割线和字号建立层级。
- 列表项使用 `10px` 圆角和 `--border-subtle`，不重复套卡片。

### 4.5 加载、空态与错误

- 页面加载：`.loading-page` 居中，使用浅色图标加简短说明，不用大面积白屏。
- 生成等待：`.waiting-card` 使用三阶段步骤列表，当前步骤实心蓝，已完成实心绿。
- 空态要给出解释和下一步，不使用只写“暂无数据”的空白块。
- 错误态用 `.fail-panel`，文案说明发生了什么、可以怎么处理。

## 五、页面模块规范

### 5.1 全局壳层

全局结构由 [AppShell.tsx](../src/components/layout/AppShell.tsx) 负责：

- 顶部：左侧阶梯几何 Logo + “知阶 Knowledge Steps”，右侧 slogan + “开始寻路”胶囊按钮。
- 主内容：`.page` 承载各路由页面。
- 底部：中心标语“每一个知识，都有它的台阶”，两侧各 60px 淡出细线；下方保留 Mock 演示说明。

### 5.2 首页

首页严格按以下信息顺序排列：

1. Hero：左侧文案 + 搜索框 + 快捷芯片；右侧三列“知识检索 → 知识编译 → 路径推演”看板。
2. 数据指标栏：三个产品事实数据 + 一句产品态度引文。
3. HOW IT WORKS：三张步骤卡，每张卡内有一个小型 UI 演示。
4. Mock 演示说明。

右侧看板包含浮层机器人气泡、手写批注和“更多可能”外延节点；这些是品牌装饰，不承载关键功能，移动端允许隐藏低价值装饰。

### 5.3 问答页

- 顶部工具栏：返回首页、当前目标、Mock 演示说明。
- 左侧问卷卡：答题进度条、导师提示、当前题目、四个答案选项、上一题。
- 右侧状态轨：已掌握、待补齐、正在确认、尚未确认四组。
- 答案自动保存并前进，重复提交不重复计数；已完成后修改答案需要重新生成结果。

### 5.4 结果页与资料侧栏

- 结果 Hero：目标名称、待补齐数量，数量不含目标本身。
- 路径图按 level 分层，保留并行分支，节点可点击。
- 目标节点视觉上比普通节点更突出，但不是所有内容都做成卡片。
- 资料侧栏用右侧抽屉，资源状态分别处理 `READY`、`EMPTY`、`FAILED`、`NOT_APPLICABLE`，不伪造作者或点赞数。

## 六、交互与动效

- 页面进入使用 `.enter`：`320ms` + `cubic-bezier(0.16, 1, 0.3, 1)`，只动 `opacity` 和 `transform`。
- 普通 hover 状态约 `150–180ms`，只改变颜色、边框、位移或缩放。
- 进度条宽度变化约 `420ms`，保留平滑补间。
- 高度变化不使用直接动画，统一用状态切换或 `grid-template-rows`。
- 必须支持 `prefers-reduced-motion`，关闭非必要位移动画。

## 七、响应式与无障碍

- 断点：`980px` 从双栏切换为单栏，`700px` 做移动端紧凑布局。
- 触控目标不小于 40px，关键按钮优先达到 44px。
- 使用 `:focus-visible` 提供键盘焦点环，不允许移除 outline 后不补充替代样式。
- 保持 `skip-link`，主内容区域使用 `id="main-content"`。
- 图标按钮必须有 `aria-label`；装饰元素使用 `aria-hidden="true"`。
- 图片或 SVG Logo 不使用文字替代内容作为关键信息唯一来源。

## 八、文案风格

- 全部使用简体中文，专业术语可保留英文，但需要解释或由上下文明确含义。
- 按钮写动作与结果，不写“确定 / 提交”。
- 错误文案说明“发生了什么、为什么、怎么办”，不指责用户。
- 自评页面反复强调“不是能力考试”，不出现能力分数或准备度百分比。
- 所有 Mock 数据必须可见地标注“演示数据 / Mock 演示”，不冒充真实来源。

## 九、实现落地与一致性检查

### 9.1 单一事实来源

- 设计变量统一写在 [styles.css](../src/styles.css) 的 `:root`。
- Ant Design 的主题 token 在 [main.tsx](../src/main.tsx) 同步主色 `#5b61f6`。
- 品牌文案与原则记录在 [.impeccable.md](../../.impeccable.md)。
- 页面结构以 [FRONTEND.md](FRONTEND.md) 为技术依据。

### 9.2 新增页面前的自检清单

在提交任何前端页面改动前，逐项确认：

- [ ] 颜色、圆角、阴影、字体是否全部来自 `:root` 变量。
- [ ] 是否复用了现有 `.primary`、`.outline`、`.card`、`.badge` 等基础样式。
- [ ] 按钮是否具备 hover、focus-visible、active、disabled 状态。
- [ ] 页面是否保持 1240px 版心、24px 安全间距和 64px 导航高度。
- [ ] 是否在 `980px` 与 `700px` 两个断点下重新检查布局。
- [ ] 加载、空态、错误、失败四类状态是否都有对应 UI。
- [ ] 是否尊重 `prefers-reduced-motion`。
- [ ] 图标、图片、链接是否补充了必要的 ARIA 或替代文本。
- [ ] Mock 数据是否明确标注，避免误导用户。
- [ ] 文案是否使用真实换行和简体中文，且没有冗余重复。

本文档与 `.impeccable.md`、`styles.css` 保持一致；设计方向或品牌色发生变化时，应同时更新三处。
