# AI JSON 校验与修复

两次模型响应分别接入 `GraphJsonValidator`（图谱）与 `QuestionJsonValidator`（问卷），共用 `GeneratedJsonSupport` 处理语法。先在内存进行确定性修复；生成内容仍未通过校验时，每个阶段最多额外调用同一模型纠正一次。正常成功不增加请求。

## 可自动修复

- 完整的 JSON Markdown 代码围栏、首部 BOM、首尾空白。
- 尾逗号、单引号字符串、未加引号的字段名和 Java 风格注释。
- 缺失或 null 的数组补为 `[]`；缺失或 null 的文本补为 `""`。
- 整数 ID 转为字符串；保留字符串中的内容，不用全局字符替换修改正文。
- 忽略契约外字段；返回值只包含领域对象规定的字段。
- 图谱完全相同的节点记录和连线去重；同 key 内容冲突、同名不同节点仍拒绝，不猜测合并关系。
- 问卷根据输入节点顺序整理。

## 修复后的业务校验

图谱描述 `description` 和 `targetDescription` 允许为空，仍限制最多 1000 字；模型提示词仍要求生成有效描述。问卷提示 hint 可为空。

名称、key、连线端点和题干即使被补为空，也无法通过业务校验。不能凭空补充事实、节点、关系或题目。继续检查图谱数量、重名、环、可达性，以及问卷数量、ID覆盖和题干有效性。

缺失所有节点会成为空图，由界面提示用户补充目标后重试，不冒充成功学习路径。

## 不修复的情况

重复 JSON 字段、多份 JSON、截断内容、数组/对象类型错误、任意前后解释文字均拒绝。原始内容上限 100 万字符，不对不确定内容猜测补括号。

语法或字段类型无法修复：`MODEL_JSON_PARSE_ERROR`；图谱语义不合法：`GRAPH_VALIDATION_FAILED`；问卷不完整或映射不合法：`QUESTION_VALIDATION_FAILED`。超时分类不变。

验证覆盖格式修复、空值补全、整数ID、文本保真、重复字段/截断拒绝、关键内容缺失和未知节点拒绝。

## 有限纠正与诊断

首次生成内容未通过语法或业务校验时，保留原始任务与系统提示，将失败类别和上次输出发送给同一模型，要求重新给出完整 JSON；上次输出超过 32000 字符时不回传正文。纠正结果再次通过同一套校验才可入库，仍失败则返回原有错误码。每阶段最多两次请求，失败场景可能增加一次模型调用的等待与费用。

HTTP、鉴权、超时、上游响应信封错误及 finish_reason 非 stop 不进入内容纠正，不猜测接受截断数据。缺失关键事实不由本地代码编造；不会为通过校验随意添加边或删除冲突节点。

日志记录阶段、尝试次数、错误码和固定原因类别（例如 GRAPH_CYCLE、NODE_CANNOT_REACH_TARGET、QUESTION_COUNT_MISMATCH），不记录原始输出、用户目标和凭证。客户端仍收到原有统一提示。

## 层级与界面边界

`GraphValidator` 校验最多 20 个前置节点、210 条边、节点名称与标识、重复、环及所有前置到目标的可达性；根据最长依赖路径计算 level。15 个及以下前置节点以包含目标最多五层为优化目标；超过时以 GRAPH_DEPTH_EXCEEDED 请求一次优化。原图通过全部业务校验后才可作为回退：优化超时、结构无效或仍超层时保留合法图谱，不因层数报结构失败；优化结果通过校验且满足层数时使用新结果。没有合法图谱可回退时仍按原规则失败。金字塔宽度、生成层宽及 16～20 个前置节点的层数仍属于提示词约束。历史已保存图谱不会自动重排，需重新生成。

前端每行最多五个节点，超出换行不产生新逻辑层；校验器不为适配布局添加假节点或假关系。零前置节点可能来自目标含糊、模型输出或目标本身，不应确定归因于错别字。
